# Expression des besoins — Frostia Games

## 1. Présentation du projet

**Frostia Games** est un portfolio web personnel conçu pour présenter mes projets, mes créations et mes futurs jeux vidéo dans un espace unique.

Le projet a été développé avec **Django** afin de disposer d’une base technique stable, structurée et évolutive. La première version a volontairement été limitée à un périmètre réduit pour garantir un résultat fonctionnel, responsive, documenté et déployé en ligne.

---

## 2. Contexte

Dans le cadre de ma formation de Développeur Web et Web Mobile, j’avais besoin d’un projet permettant de mettre en pratique plusieurs compétences :

- concevoir une interface utilisateur ;
- réaliser des pages web statiques et dynamiques ;
- structurer une application avec Django ;
- utiliser une base de données relationnelle ;
- administrer certaines données ;
- adapter l’interface aux différents formats d’écran ;
- documenter, tester et déployer l’application.

Le projet devait également pouvoir servir de support de présentation pour mes futurs travaux professionnels et personnels.

---

## 3. Besoin principal

Le besoin principal était de créer un portfolio web capable de :

- présenter clairement mon univers et mes projets ;
- distinguer les créations en cours des projets jouables ;
- proposer une navigation simple ;
- fonctionner sur ordinateur, tablette et smartphone ;
- être administrable sans modifier directement le code ;
- être accessible en ligne ;
- pouvoir évoluer progressivement.

---

## 4. Utilisateurs visés

### Visiteurs

Les visiteurs peuvent consulter :

- la page d’accueil ;
- la présentation générale de Frostia Games ;
- les créations ;
- les projets jouables ;
- les informations disponibles sur l’avancement des projets.

### Administrateur

L’administrateur dispose d’un accès privé à l’interface d’administration Django afin de gérer les contenus prévus par l’application.

Aucun compte public n’est proposé dans la version 1.

---

## 5. Objectifs prioritaires

1. Créer une identité visuelle cohérente.
2. Proposer une navigation claire.
3. Réaliser une interface responsive.
4. Mettre en place une architecture Django simple.
5. Utiliser une base de données SQLite.
6. Disposer d’une interface d’administration privée.
7. Déployer l’application sur Render.
8. Produire une documentation technique complète.

---

## 6. Fonctionnalités retenues pour la version 1

La version 1 comprend :

- une page d’accueil ;
- une page « Mes créations » ;
- une page « Projets jouables » ;
- une navigation desktop avec barre latérale ;
- une navigation mobile adaptée ;
- une mise en page responsive ;
- une administration Django privée ;
- une base de données SQLite ;
- un déploiement en ligne sur Render ;
- une documentation d’installation, d’architecture, de tests et de déploiement.

---

## 7. Limites du projet

Le périmètre a volontairement été réduit afin de privilégier la stabilité et la qualité.

Les éléments suivants ne sont pas inclus dans la version 1 :

- création de comptes utilisateurs publics ;
- système de commentaires ;
- messagerie interne ;
- paiement en ligne ;
- galerie complète ;
- formulaire de contact avancé ;
- système de notation ;
- fonctionnalités communautaires ;
- gestion NoSQL réellement intégrée à l’application.

Ces fonctionnalités pourront être étudiées dans une version ultérieure si elles répondent à un besoin réel.

---

## 8. Contraintes

### Contraintes techniques

- utilisation de Django et Python ;
- interface compatible avec les navigateurs modernes ;
- adaptation aux principaux formats d’écran ;
- base SQLite pour la version 1 ;
- déploiement sur Render ;
- maintien d’une architecture simple et compréhensible.

### Contraintes de temps

Le projet devait être suffisamment limité pour pouvoir être terminé, testé, documenté et présenté dans le cadre de la formation.

### Contraintes de qualité

Le site devait être :

- lisible ;
- responsive ;
- stable ;
- maintenable ;
- documenté ;
- déployable ;
- cohérent visuellement.

---

## 9. Livrables attendus

- les maquettes desktop et mobile ;
- le code source Django ;
- les templates HTML ;
- les fichiers CSS ;
- la base SQLite ;
- l’interface d’administration ;
- les documents de conception ;
- les preuves de fonctionnement ;
- les documents de tests ;
- le journal de déploiement Render ;
- le dossier projet final.

---

## 10. Critères de réussite

Le projet est considéré comme fonctionnel lorsque :

- les trois pages principales sont accessibles ;
- la navigation fonctionne ;
- l’affichage s’adapte aux différents écrans ;
- l’administration Django est accessible de manière sécurisée ;
- les données prévues sont correctement affichées ;
- l’application est déployée ;
- les principales fonctionnalités sont testées ;
- la documentation permet de comprendre et de réinstaller le projet.

---

## 11. Évolutions envisagées

- ajouter une galerie ;
- intégrer un formulaire de contact ;
- enrichir les contenus administrables ;
- ajouter un historique de progression ;
- intégrer des graphiques ;
- étudier l’usage d’une base NoSQL pour certains types de données ;
- améliorer l’accessibilité ;
- ajouter de nouvelles pages sans remettre en cause l’architecture existante.

---

## 12. Conclusion

Frostia Games répond au besoin de disposer d’un portfolio personnel moderne, responsive et évolutif.

La version 1 ne cherche pas à intégrer un grand nombre de fonctionnalités. Elle constitue une base stable permettant de présenter les projets, de démontrer les compétences techniques mises en œuvre et de préparer les évolutions futures.
